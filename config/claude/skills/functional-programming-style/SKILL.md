# functional-programming-style

- 関数は純粋関数と副作用を持つ関数に分ける。1 つの関数に両方を混ぜない
  - 副作用とは、IO (ファイル、ネットワーク、DB、ログ出力)、現在時刻の取得、乱数生成、環境変数の読み取り、引数以外の状態の読み書きのこと
  - 引数で受け取った DB 接続や HTTP クライアントなどを通じた操作も副作用に含める
  - 判断や変換のロジックは純粋関数に書く。副作用を持つ関数は、副作用の実行と純粋関数の呼び出しだけを行う
  - 純粋関数はモックなしで単体テストできること
  - 分離できない場合は、混ぜる前に理由を示してユーザーの許可を求める
- 値は immutable にする。変更が必要なら新しい値を作って返す
- 状態や不変条件は型で表現する
  - 状態が異なれば別の型にする (例: 未検証の入力と検証済みの値)
  - 取りうる値が有限なら bool や string ではなく列挙型にする
  - 失敗しうる関数は、失敗することが戻り値の型から分かるようにする
- 上記はその言語の標準的な手段で実現する。Maybe や Either のような他言語の構造を模倣したクラスやライブラリを導入しない
