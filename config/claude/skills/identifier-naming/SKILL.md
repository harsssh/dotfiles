# identifier-naming

## 名前に込める情報

- `get`、`process`、`handle`、`data`、`Manager`、`Util` のような、何にでも当てはまる語を避け、具体的な語を選ぶ
- 単位や値の制約を名前に含める (例: `timeoutSecs`)。ただし、型で表せるものは型で表し、名前で補うのは型で表せないときだけにする
- 何をするか、なぜあるかで名付ける。呼ばれるタイミング (例: `onInit`) で名付けない
- 変数名を型名の繰り返しにせず、そのインスタンスを他と区別する性質で名付ける

## 誤解を防ぐ

- bool は `is`、`has`、`can` などで真偽の問いと分かる形にし、肯定形にする
- 1 つの概念には 1 つの語を使う。同じ概念を別の語で呼ばず、別の概念に同じ語を使わない
- 仕様書やドメインの語彙を使う。`Processor`、`Transformer` のような計算機科学の用語で代用しない

## 長さと形

- 名前の長さはスコープの広さに合わせる。狭いスコープなら短い名前でよく、広いスコープほど説明的にする
- 英文法的に自然な形にする。関数は動詞句、型は名詞句、bool は述語にする
- 言語の命名慣習に従う

## 名前が決まらないとき

- 名前に and が入る、長くなりすぎる、汎用的な語しか浮かばない場合は、責務が多すぎるサインと考える。名前を妥協せず、境界を見直す
- 既存の名前を段階的に直すときは、evolutionary-naming skill を使う
